## coding agent 常用概念

### 1. Sandbox（沙箱）

执行代码/命令的受限环境。

- 作用：隔离影响、控制权限（文件系统、网络、可执行命令）
- 常见价值：防止错误命令影响主环境，便于安全地测试
- 常见问题：文件读写受限、网络受限、环境变量不完整

### 2. Workflow（工作流）

从需求到交付的一套固定执行步骤。

- 典型步骤：理解目标 -> 拆分任务 -> 修改代码 -> 验证 -> 汇报
- 价值：减少遗漏，提升协作可复现性
- 常见形态：Plan/Implement/Verify/总结（即“先想方案再落地”）

### 3. Frontmatter（Front Matter）

内容文件开头的元信息块（YAML/TOML/JSON）。

- 作用：驱动列表页筛选、排序、分类、标签和草稿控制
- 对本博客常见字段：`title`, `date`, `updated`, `summary`, `tags`, `category`, `type`, `importance`, `draft`

### 4. Content Collection（内容集合）

Astro 对内容目录的结构化定义。

- 作用：统一校验文章字段，保证跨页面查询一致
- 本仓库常见集合：`blog`、`notes`、`important`
- 价值：减少运行时错误，便于页面查询与分页

### 5. Context（上下文）

模型可见的输入信息（当前任务、历史记录、代码片段、文件内容）。

- 影响：上下文越完整，回答越准确；越长越可能带来噪声
- 管理技巧：保留关键约束、文件路径、最近改动，删掉无关内容

### 6. Tool Call（工具调用）

模型在本地执行动作的方式（读文件、写文件、查命令等）。

- 价值：提升确定性与可追踪性
- 常见策略：一次调用单一目的，必要时先做目录确认再写入

### 7. Prompt（提示词）

用户向 agent 下达的任务描述。

- 好提示词通常包含：目标、约束、优先级、验收标准
- 对编码最重要的是：告诉模型“要改哪类文件”“避免做无关验证”这类边界

### 8. Idempotent（幂等）

重复执行结果一致。

- 对任务很关键：脚本或部署命令可反复运行不产生副作用
- 常见要求：不存在重复创建、重复追加导致脏数据

### 9. Lint/Build（静态检查与构建）

代码质量和可发布性保障。

- 作用：检测语法/类型问题，确保页面可正常生成
- 备注：这类命令有时会触发较重的资源消耗，按需执行即可

### 10. Commit（提交）

一次可追溯的修改快照。

- 价值：便于回滚、协作和问题复盘
- 建议：每完成一个可交付小块就提交，信息清晰如 `feat: add coding-agent concepts note`
